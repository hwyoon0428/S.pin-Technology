# 자가개선 루프

이 절차는 Codex에 저장소 개선을 요청할 때 한 번 실행합니다. 정기 실행과 자동 PR 생성은 설정되어 있지 않습니다.

## 실행

Codex Cloud에서 이 저장소를 선택하고 다음과 같이 요청합니다.

> 자가개선 루프를 한 번 실행해 줘. 현재 저장소에서 근거가 있는 개선 한 건을 선택하고 구현·검증한 뒤 결과를 기록해 줘.

1. `AGENTS.md`, 관련 위키, Git 상태, 기존 기록과 프로젝트의 실제 검증 방법을 확인합니다. 사용자 변경 사항은 보존합니다.
2. 실패한 검사, 사용자의 피드백, 문서의 불일치 등 확인 가능한 근거로 후보를 찾습니다. 후보가 없으면 임의의 변경을 만들지 않고 그 사실을 보고합니다.
3. 영향과 검증 가능성을 고려해 한 건을 선택하고, 문제·기준선·완료 조건을 기록합니다. 저장소가 초기 단계라 실행 방법이나 테스트 명령이 없으면 추측하지 않습니다.
4. 범위를 제한해 변경하고 적합한 검증을 수행합니다. 실패하면 원인을 조사하고 수정 후 다시 검증합니다. 검증할 수 없다면 이유와 남은 위험을 기록합니다.
5. 결과를 아래 양식으로 `docs/improvements/`에 기록하고, 변경·검증·한계를 사용자에게 보고합니다. 중요한 설계 결정은 별도로 `docs/decisions/`에 남깁니다.

검증된 개선은 `self-improvement/`로 시작하는 같은 저장소의 브랜치에서 `main`으로 PR을 생성합니다. 저장소 소유자가 생성한 준비된 PR은 자동 병합 워크플로가 처리하며, GitHub의 브랜치 규칙과 필수 검사는 계속 적용됩니다. GitHub 저장소에서 자동 병합 및 Actions의 쓰기 권한을 허용해야 합니다. 실패하면 실행 로그를 확인하고 결과를 보고합니다.

다음 실행에서는 이전 결과와 미해결 항목을 확인해 회귀나 반복되는 문제를 우선 살펴봅니다. 기록은 증거이며, 기록 자체가 개선 효과의 증명은 아닙니다. 비밀정보나 개인정보는 기록하지 않습니다.

## 기록 양식

파일명: `YYYY-MM-DD-간단한-주제.md` (같은 날 충돌하면 구분자를 추가)

```markdown
# 개선 제목

- 날짜:
- 문제와 근거:
- 변경 전 기준선:
- 완료 조건:
- 변경 내용:
- 검증 명령 또는 확인 방법과 결과:
- 미실행 검증과 이유:
- 결과 및 남은 위험:
- 후속 후보:
```

변경의 효과를 비교할 수 있다면 동일한 조건과 기준을 전후에 적용하고, 측정할 수 없는 항목은 미측정으로 표시합니다.
